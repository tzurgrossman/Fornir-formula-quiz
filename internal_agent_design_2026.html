1. Executive Summary

This document outlines the architecture for a minimalist, headless AI agent system designed for internal operational support. Leveraging the 2026 AWS Bedrock ecosystem, the system moves away from custom vector databases and complex orchestration code, relying instead on managed Bedrock Agents and native Model Context Protocol (MCP) integration.

Key Goal: Correctness over conversation. The system prioritizes strict adherence to rules defined in a "Structured Knowledge Layer."

2. System Architecture (High Level)

The architecture is fully serverless. Users interact via a CLI or Script, which invokes the Bedrock Agent Runtime. The Agent uses a single "MCP Gateway" Lambda to interface with existing internal tools.

3. Detailed Component Design

3.1 The "Brain" (Model & Orchestration)

We utilize Claude 4.5 Sonnet for the agent runtime due to its superior reasoning capabilities and reduced hallucination rates compared to v3.5. Temperature is set to 0.0 to enforce strict rule following.

3.2 Knowledge Layer (The "Memory")

Instead of standard chunking, we use Hierarchical Indexing powered by Claude 4.5 Opus during ingestion. Opus pre-processes Markdown files into logical "Q&A" blocks before vectorization, ensuring the agent retrieves concepts rather than just matching keywords.

3.3 Tool Layer (MCP Gateway Pattern)

To avoid managing hundreds of Lambda functions, we implement a single Generic MCP Client Lambda. The Bedrock Agent passes the tool name and parameters to this Lambda, which acts as a proxy to your internal MCP servers.

Component Specification Role

4. Phased Implementation Plan

Phase 1: Stateless Kernel (Weeks 1-2)

  • Goal: Functional reasoning engine that can read S3 docs and call 1 tool.
  • Infrastructure: Deploy S3 Bucket, Knowledge Base, and single Lambda via CDK.
  • Constraint: No conversation history. Every request is isolated.

Phase 2: Stateful Context (Weeks 3-4)

  • Goal: Enable "Chat" and User Preference learning.
  • Action: Check "Enable Memory" in Bedrock Console.
  • Feature: Agent learns "User X prefers Python responses" automatically.

5. Security & Operational Overhead

  • Authentication: Relies on standard AWS IAM. No custom API keys.
  • Network: Lambda runs inside VPC to access internal MCP servers.
  • Cost Model: Pay-per-token. Estimated at ~$50/month for 30 users (low volume).
